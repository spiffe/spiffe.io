Choose an architecture based on authority boundaries and availability needs. Start with [scaling SPIRE](/docs/spire/planning/scaling_spire/) for a single trust domain.

Use [nested SPIRE](/docs/spire/architecture/nested/) when downstream servers should issue identities under the same trust domain. Use [federation](/docs/spire/architecture/federation/) when independently operated trust domains need to authenticate each other's workloads. Follow the linked examples with their pinned dependencies.
